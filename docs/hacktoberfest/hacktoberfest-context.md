## General background

Hacktoberfest is an annual October program encouraging participation in open
source. Historically, its contribution workflow has included pull requests on
GitHub and merge requests on GitLab. Participation criteria and rewards can
change between editions.

Useful open-source work can include bug fixes, features, documentation,
translations, accessibility improvements, design, and tests. Whether a specific
kind of work counts toward the global program or the local event must be checked
against their respective current rules.

For preparation, distinguish three outcomes:

1. Attending and completing the local event's activities or submission.
2. Producing work that the relevant maintainers find useful and accept.
3. Having a contribution recognized by the global Hacktoberfest program.

Achieving one does not establish the others.

## Practical preparation for a contribution-focused event

- Choose a project you can understand and run within the available time.
- Read its README, contribution guide, conduct policy, and license.
- Check that the issue is still relevant and whether someone is already working on it.
- Use an existing issue or establish agreement with maintainers before investing heavily in a change.
- Keep the contribution focused on a real need. Include enough explanation and validation for review.
- Allow time for setup, feedback, and revision; submitting a pull request does not guarantee immediate acceptance.

These are workflow recommendations. They are not event-specific requirements.
